# Обновление доски lili.math

Интерфейс публикуется через GitHub Pages. Права доступа требуют отдельного обновления существующего сервера хранилища. Оно сохраняет рисунки, файлы, адрес сервера и настройки Caddy.

В терминале сервера под администратором:

```bash
curl -fsSL https://raw.githubusercontent.com/liliya-math/excalidraw/master/lili-server/update-workspace.sh -o /tmp/lili-workspace-update.sh
bash /tmp/lili-workspace-update.sh
```

Скрипт проверяет синтаксис файлов, делает резервную копию приложения, перезапускает хранилище и канал совместного рисования и проверяет `/storage/capabilities`. При неудаче восстанавливает приложение. База рисунков не удаляется. Активные участники могут кратковременно переподключиться. Для ручной проверки: `curl -fsSL http://127.0.0.1:3003/storage/capabilities`.

## Учитель и ученик

1. Открыть существующую совместную доску. Уроки → Защита → «Включить права учителя и ученика».
2. Сохранить ссылку учителя. Это секретная ссылка восстановления доступа; её не отправляют ученику.
3. Отправить ученику новую ссылку ученика и заменить старую ссылку в его кабинете. Старый адрес без ключа доступа останется доступен для просмотра.
4. Выделить условия, рисунки или рамку урока, затем «Защитить выделенное или закреплённые фоны». Если ничего не выделено, будут защищены закреплённые объекты.
5. «Я веду этот урок» отмечает текущего участника для кнопки «За учителем».

Ссылки содержат ключи в части после `#`, которая не отправляется веб-серверу. На сервере хранятся только хеши ключей доступа. Рисунки и защищённый слой шифруются браузером с ключом комнаты. Защищённый слой хранится отдельно: ученик не может заменить его своей версией общей доски. Файлы защищённых условий нельзя перезаписать ключом ученика. На канале совместной работы сообщения без действующего ключа записи не транслируются другим участникам; адрес комнаты и подписки на следование проверяются сервером.

У существующих комнат первое включение защиты должно делать доверенное лицо. До этого они остаются в прежнем совместном режиме. Это переход от старых общих ссылок, а не установление личности по имени ученика.

## План и история

Личные заметки и скрытые текстовые шаги находятся только в IndexedDB браузера. В общую доску отправляется только явно открытый шаг. Удаление шага из личного плана не удаляет ранее опубликованный текст. План переносится отдельным JSON-файлом.

В браузере хранятся до 12 снимков, суммарно до 100 МБ, один снимок до 40 МБ. Автоснимки при изменениях создаются раз в 3 минуты при открытой доске. Перед восстановлением сохраняется текущая версия. Сервер также оставляет до 12 зашифрованных резервных версий с интервалом не чаще 5 минут; они доступны администратору в DATA_DIR/history. Они не заменяют ежедневный архив сервера.

## Видеосвязь

Оба участника открывают одну совместную комнату, нажимают «Видео», затем «Включить камеру и подключиться». Видео и звук передаются через WebRTC между браузерами. Согласование соединения идёт по существующему зашифрованному каналу доски. Камера не включается автоматически, закрытие звонка останавливает все медиадорожки.

По умолчанию используется STUN Cloudflare. В сетях, где прямое соединение запрещено, нужен TURN. Хранилище поддерживает серверные переменные:

- `TURN_URL`: адреса настроенного TURN-сервера через запятую, например `turn:turn.example.org:3478?transport=udp,turn:turn.example.org:3478?transport=tcp`.
- `TURN_SECRET`: общий секрет HMAC, совпадающий с настройкой TURN REST API на сервере.

API выдаёт браузеру временные TURN-учётные данные на час; сам секрет не выдаётся. Установка и сетевые правила TURN зависят от провайдера. До настройки нельзя обещать работу видео в любой сети.

## Ограничения инструментов

- Геометрические построения создаются по параметрам; подписи не пересчитываются при ручном растяжении.
- HTML-материалы добавляются как интерактивные встроенные страницы, PDF как закреплённые изображения. Содержимое встроенных страниц не попадает в итоговый PDF; используйте исходный PDF задания.
- Личные планы и снимки браузера не синхронизируются автоматически между устройствами.
